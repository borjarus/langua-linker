# ADR-13: Opt-in usage metrics and crash reports

- Status: Proposed (2026-11-17); implemented in Phase 16 as a **local-only** store. Acceptance needs the D-08 decision (vendor/hosting/retention) and a beta with the counting verified end to end.
- Plan references: Phase 16 step 1 (1–5) and DoD "beta metric counting / crash symbols verified"; Phase 12 (telemetry consent, versioned and revocable); §3/§5 logging policy; D-08

## Context

The settings have stored a telemetry consent since Phase 12 (off by default, versioned text), but nothing used it. Logs are already redacted by field name and a Rust panic leaves a content-free `last-crash.json` (Phase 7). The plan asks for opt-in events (session, rating, generation latency/error, favorite, crash) without text, prompts or secrets; a D7 cohort with a pseudonymous id; local diagnostics without network consent; and checks against the targets D7 ≥ 25 %, cold start median < 2 s, generation p90 < 4 s, favorite ≥ 20 %, true retention 85–92 %, crash-free ≥ 99.5 %. D-08 (who receives the data, where it is hosted, how long it is kept) is still open, and the Privacy screen promises "this version sends nothing".

## Decision

1. **Closed event set** (`application::telemetry::MetricEvent`): `appStarted{coldStartMs}`, `sessionEnded{reviews, durationMs}`, `rated{1–4}`, `undone`, `generated{latencyMs, ok}`, `generationRetried`, `favorited`, `restored{ok}`, `nativeCrash`, `clientError`. Each is a name plus at most two integers. There is no field that can hold text, so card content, prompts, keys and file names cannot enter by mistake. Unknown rows (a newer build) are skipped on read.
2. **Separate store** `telemetry.sqlite` next to the collection (`infrastructure::telemetry::LocalTelemetry`), never inside it: backups do not carry metrics, a restore does not bring back someone's old metrics, and opting out deletes them without touching the collection.
3. **Consent drives the store.** The shell makes the store follow `telemetryOptIn` on start, after `updateSettings`, and after a restore or reset succeeded. Opting in creates a random 128-bit id and the cohort start; opting out deletes the id and every event and runs `VACUUM`, so the id does not survive in free pages (tested). A new opt-in is a new cohort with a new id. Nothing is recorded while not opted in.
4. **Pseudonymous, not anonymous** (step 2). The id identifies this installation's metrics; the UI says so ("pseudonymous: tied to a random ID of this installation, not to you") and shows only its first 8 characters. The earlier wording "anonymous" was corrected.
5. **Where events come from.** Rating, undo, favorite and session end: the study commands, only when not replayed. Provider latency, failures and retries: the LLM service (`with_telemetry`), cancelled waits excluded. Restores: a decorator on the event sink that sees terminal restore jobs. A crash: on the next start the shell takes `last-crash.json` once (moved to `previous-crash.json`), logs its version and source location, and records `nativeCrash`. Cold start and WebView errors: two commands outside `AppApi` in the `metrics` capability — `report_startup { coldStartMs }` (time from navigation start to the first frame, once per process, ≤ 10 min) and `report_client_error { kind: "error" | "unhandledRejection" }` (no message, no stack; at most 20 per process; `deny_unknown_fields` refuses anything more). The WebView error is also written to the local log as `code=<kind>`, consent or not — that is local diagnostics (step 5).
6. **Summary and targets** (`summarize`). Day indexes count whole 24-hour periods since the opt-in (time-zone free); D7 = active (start, rating or session) on day 7, known once day 7 has passed. Medians and p90 use the nearest rank. A target is judged only with enough samples (cold start 5 starts, generation and favorites 10, crash-free 200 starts — one crash in fewer starts already misses 99.5 % and is reported as missed). D7 is marked `cohortOnly`: one device cannot judge a cohort share. True retention is not duplicated here; it is the statistics screen's definition (Phase 12).
7. **No network** until D-08. `get_usage_metrics` returns the summary; the Privacy screen shows it under the consent switch with a "Copy summary" button, so a beta tester can hand it over deliberately. An uploader later is one more adapter behind the same store (batch the summary, not raw events; EU hosting; retention as decided) and needs its own consent text version.
8. **Retention on the device**: events older than 180 days are deleted on start; at most 50 000 rows (oldest first).
9. **Crash symbols** (step 4): the native report holds `file:line` of the panic — readable without symbol files because it comes from `Location`, not a stack. Native crashes outside Rust panics (JNI, WebView process) and symbolicated stacks need a vendor SDK or the platform consoles (Play Console vitals, Xcode Organizer); that is part of D-08.

## Consequences

- No contract version bump: the three commands are platform adapters outside `AppApi` (capability `metrics`, every variant), like the Phase 15 speech commands.
- Failures of the store are logged and swallowed; a missing or broken `telemetry.sqlite` never blocks study.
- The beta can measure on each device and compare by copied summaries; cross-device cohort numbers (D7 ≥ 25 %, crash-free across users) need D-08.
- Open: D-08 vendor/hosting/retention, upload consent text, Play/App Store data-safety entries for whatever is uploaded (Phase 17), WebView crash capture beyond uncaught errors.
